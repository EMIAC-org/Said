Model size, disk aur RAM

S1 family, pichli research ke alternatives aur AirNote ke current local models yahan compare kiye hain. Download size exact file metadata se liya hai. RAM jahan measured nahi hai, wahan neeche planning estimate diya hai.

Parameters

0.6B ka matlab 60 crore model parameters. Yeh download ka size nahi hai. “Nemotron 3.5” mein 3.5 version hai; is ASR model ka parameter class 0.6B hai.

Disk / SSD space

Selected weights ka download aur permanent disk footprint lagbhag same hai. Runtime, tokenizers, saved audio aur duplicate caches alag space lete hain. Yahan MB/GB decimal units hain.

RAM / unified memory

Chalte waqt weights ke saath working buffers aur context bhi memory lete hain. Neeche ke estimates model runtime ke liye hain; OS aur baaki apps ka RAM inmein included nahi hai.

*RAM estimates ka matlab: single-user, short dictation ke initial evaluation ke liye mera suggested budget. In selected quantized builds ka publisher-certified minimum nahi mila, aur is machine par model run nahi hua. Audio length, runtime, context aur hardware se usage badlega. Is range ko guarantee ya measured minimum mat samajhna.

How good is it?

Promising evidence, narrow coverage

The reported result

Superwhisper reports 94.8% token accuracy over 7,519 cases spanning 104 transcripts. It reports exact email-address output in 92% of cases and degenerate output in fewer than 1%. These are publisher measurements, not an independent AirNote evaluation.

Published evaluation ↗

The unanswered question

Token accuracy does not measure audio recognition, complete-utterance correctness, or preserved intent. A missed “not”, changed amount, or omitted sentence can ruin a dictation despite a high aggregate score. AirNote needs these failures counted separately.

The largest mismatch

AirNote promises Hinglish that keeps the speaker's meaning.

Its prompt explicitly protects Roman Hindi, English terms, politeness, numbers, and names. S1-mini's English scope leaves that contract unverified. Qwen ancestry alone does not establish multilingual performance after a specialized fine-tune.

Integration failures already reported elsewhere

A FluidVoice contributor reproduced sentence dropping after the app prepended generic cleanup rules to S1-mini's prompt. The app issue is closed. It is evidence to keep the required prompt intact, not a model-wide failure rate. FluidVoice report ↗

An EnviousWispr issue reports empty completions with S1-mini through Ollama and recovery to raw text. Its root-cause hypothesis is explicitly unvalidated. Empty-completion report ↗

Superwhisper itself shipped Intel stability and model consistency improvements on August 20 and 26. Release history ↗

Exact runtime settings matter

Use the published system prompt and supported control values, disable thinking through the chat template, and set temperature to zero. Do not reuse AirNote's full prompt. The documented llama.cpp launch is below. Runtime instructions ↗

llama-server -hf superwhisper/s1-mini-GGUF:Q4_K_M \
  --jinja --chat-template-kwargs '{"enable_thinking":false}' --temp 0

This command is reference material; it was not run. Keep passes around 1,000 input tokens or less. Filler-only input can legitimately produce empty output. A blank completion for meaningful speech needs separate handling. Input limits ↗

The application blog shows a “balanced” tone setting, but the downloadable model lists four supported styling values and omits it. For integration, follow the released model card. Released control format ↗ Application tone UI ↗

What the license means for AirNote

The license allows use and distribution under Apache 2.0 conditions and adds model naming requirements. Preserve the license, notices, and attribution. Identify the model as “S1-mini” by “Superwhisper” with that capitalization, including inside a differently named product. Treat this as open weights with an additional term, rather than assuming an unmodified Apache license. Operative license ↗

Choose the problem first

Would it address why AirNote stopped?

The reason for scrapping AirNote was not given. These are conditional recommendations, not assumed diagnoses.

A plausible fit for English

A local cleanup pass removes a network dependency and per-request provider charges for that stage. Measure completion time, battery use and memory alongside STT. Local execution is not automatically faster on every device.

No supported multilingual case yet

Keep Hindi and Hinglish out of a production S1-mini route until a separate evaluation passes. Roman script does not turn Hindi into English. Compare preservation of language mix, names and numbers.

Test the recognizer separately

A text cleaner cannot recover speech that capture never recorded or reliably reconstruct omitted words. Freeze the recognizer for cleanup tests, then test speech models with audio and human references as a separate experiment.

The original product work remains

Capture, paste, runtime crashes and market demand still need their own evidence. Superwhisper now offers local Whisper free on macOS, which raises the bar for another general dictation app. Free local Whisper announcement ↗

Smallest experiment

English with S1-mini

Run cleanup locally with its exact input format. Keep raw text available for errors. It offers the clearest test of whether a smaller cleanup model helps.

Quality baseline

Current cloud polish

Keep DeepSeek or Gemma as the comparison for context and language preservation. Use the same transcripts; do not claim the existing route is already good enough.

Broader local comparison

Qwen3.5 4B

A larger multilingual model is a candidate for flexible prompts. Its language coverage is not evidence of accurate Hinglish cleanup; evaluate it too.

Model card ↗

If recognition was the main blocker, evaluate Qwen3-ASR separately. Its published language list includes Hindi and English. That still does not establish code-switching accuracy or Roman Hindi output, and it needs an ASR adapter. Speech-model alternative ↗

A bounded decision

Run the comparison before a restart

85% confidence

In the recommendation to run a small English evaluation. This is an engineering judgment, not a measured probability or a quality score.

Confidence in restarting the original multilingual product remains below the 80% decision threshold. The cause of scrapping it and its results on real dictations remain unknown.

Suggested evaluation budget

One or two focused days, timeboxed. This is a proposed research budget, not an estimate for shipping a new version.

Compare raw STT, the current cloud route and S1-mini on 100 locally held examples. Treat English, Hindi and Hinglish as separate groups.

  1. Freeze the transcripts. Use the existing lab pattern. Include names, technical vocabulary, amounts, negation, self-corrections, short commands and longer takes. Use a human reference, not the STT output, as truth.
  2. Judge meaning and correction effort. Count invented or omitted content, changed values and names, language drift, and edits needed before sending. Review results without model labels.
  3. Measure the full wait. Record warm and cold completion times, including the slowest 5% of cases. Measure peak memory with STT resident. Test the lowest target hardware before broadening platform support.
  4. Bound failure. For meaningful speech, preserve raw text on timeout or unusable output. Keep intentional filler suppression distinct. A local mode must not silently send text to a cloud fallback.
  5. Decide per language. Proceed only where quality holds and speed or privacy improves. A passing English comparison is not a passing Hinglish evaluation. Keep the original route selectable for rollback.

What could justify bringing it back

Less waiting, fewer corrections, and a reason to choose AirNote.

Small local models make the experiment cheaper. AirNote still needs evidence that its chosen users get more reliable dictation than they do today. The model is available to competing apps too.
