Make Scribe v2 the paid-cloud default.

Keep GPT-4o mini Transcribe as a fallback. The benchmark does not justify removing either provider, but it does justify choosing Scribe first when both keys are available.

Pipeline implication

Scribe → deterministic script cleanup → cheaper, less “smart” polish becomes viable.

Important boundary

Scribe reduces semantic correction work; it does not remove AirNote’s Romanization and formatting layer.

Why it won

AirNote’s critical failure mode is not punctuation. It is losing product names, acronyms, and English words inside Hindi speech—then asking the polish model to guess them back. Scribe gave the downstream pipeline much cleaner evidence.

01 / TERMS

6.3× more exact recoveries

Scribe retained Docker, webhook, Sentry, ZooKeeper, Kafka, CPA and Meta Ads in their useful written form.

02 / CODE-SWITCHING

English stayed English

Scribe preserved Latin-script code-switches. OpenAI frequently transliterated them into Devanagari or Urdu, increasing downstream ambiguity.

03 / SPEED

Better tail behavior

Providers split clip-level wins 8–8, but Scribe’s median was 0.80s lower and its p95 was 7.18s lower in this single pass.

What this changes

The benchmark supports simplifying the paid-cloud path while preserving AirNote’s multimodal combinations.

Default to Scribe v2

Use it when the ElevenLabs key is configured; retain OpenAI as the cloud fallback.

Keep deterministic output guards

Romanization and formatting still belong in AirNote. They are predictable transforms, unlike guessing lost terminology.

Benchmark the combination matrix next

Compare Scribe + cheap polish, Scribe + current polish, OpenAI + current polish, and local STT + strong polish on the same corpus.

Add provider bias only in round two

This result is the unbiased baseline. Keyterms or prompts should be evaluated as separate configurations, not mixed into the provider decision.

Method and limits

The test is strong enough to select a default for this voice and workload, but it is not a universal speech-recognition leaderboard.

Controlled

Same 16 WAVs, fixed model IDs, no prompt, no language hint, no keyterms, no diarization, no audio-event tags, alternating call order.

Measured

Request wall time, failures, strict technical-term recovery, output scripts, and transcript-level disagreements.

Known limitation

Only one clip has a full reference script. Surface WER is distorted when equivalent Hindi is written in Roman, Devanagari, or Urdu scripts, so it was not used as the deciding metric.

Confidence boundary

High confidence for AirNote’s current Hinglish/technical workload; medium confidence for other speakers, accents, languages, and noisy environments until the corpus expands.

Both models still failed some content: both heard STT as STD in the known-script clip, and Scribe misspelled Urban Aura. The recommendation is “best of these two,” not “solved.”
