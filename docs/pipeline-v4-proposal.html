v4 Proposal

AirNote Pipeline Architecture

End-to-end voice dictation: capture, polish, learn, correct

Flow 1: Voice to Text Flow 2: Learning Flow 3: Demotion What Changed
Key Design Principle
"One step, one job. Tier2 collects evidence. LLM makes decisions. Learning writes to DB. No step does another step's job."
🎤

Flow 1: Voice → Text

The hot path — runs every time the user speaks
Step 1

Capture

User holds Caps Lock → audio recorded at 16 kHz PCM via cpal.

  • macOS: CGEventTap (Input Monitoring permission)
  • Windows: WH_KEYBOARD_LL low-level keyboard hook
Step 2

STT (Local speech whisper.cpp)

Audio streamed over pre-warmed WebSocket → raw transcript returned.

Transcript may contain garbles: "meac", "mecorbs", "kafk". These are expected — the LLM will fix them later using evidence.

Step 3

Evidence Collection (Tier2 — READ ONLY)

Tier2 engine scans the raw transcript against known data. Produces an evidence list. Does not modify text.

  • STT aliases — meac→EMIAC, mecorbs→MACOBS
  • Edit-policy rules — learned user preferences
  • ONNX neural scorer — confidence scores for ambiguous tokens
Output: Evidence list (metadata only, never text mutations)
[{"token": "meac", "likely": "EMIAC", "score": 0.95, "kind": "alias"},
 {"token": "kafk", "likely": "Kafka", "score": 0.88, "kind": "alias"}]
Raw transcript is NOT modified. Evidence is metadata only.
Step 4

Dynamic Prompt Building

Build a context-rich prompt for the LLM using tier2 evidence. ONE filtering step — no separate phonetic filter.

4a Filter vocabulary: Only terms whose aliases matched tokens in the raw transcript (from Step 3 evidence).
4b Select few-shot examples: From user's correction history, pick 6-8 examples similar to the current transcript.
4c Build system prompt: Vocabulary table + few-shot turns + cleaning rules assembled into a single prompt.
One filtering step using tier2 evidence. No separate phonetic filter.
Step 5

LLM Polish (Scout 17B on Groq)

The LLM receives the raw transcript (untouched) plus the dynamic prompt with vocabulary hints. It makes ALL corrections using full context.

  • Fixes STT garbles: meac→EMIAC, kafk→Kafka
  • Disambiguates: meac→EMIAC vs meac→Mac based on context
  • Preserves real Hindi/English words: kaafi, mac, maine
  • Cleans grammar, punctuation, romanization
Output: Polished text — streamed token-by-token via SSE
Step 6

Post-LLM Passes (deterministic, no LLM)

Lightweight deterministic transforms that never conflict with LLM output.

  • Number formatting — "fifty" → "50", "two hundred" → "200"
  • Email recovery — reassemble addresses split by STT
Step 7

Paste

Token-by-token HID typing into the currently focused app.

  • macOS: CGEventKeyboardSetUnicodeString (Accessibility permission)
  • Windows: SendInput(KEYEVENTF_UNICODE)
  • 6ms keydown→keyup + 6ms post-keyup delays (sacred — prevents word-breaking)
🧠

Flow 2: Learning

Happens 30 seconds after paste, when the user edits
Step 1

Edit Watch

30 seconds after paste, read the text field via Accessibility API. Capture what we pasted (ai_output) vs what the user left (user_kept).

Rejection gates: stale (>30s), app switched, clipboard match (user pasted over our text).

Step 2

Diff

edit_diff::diff(transcript, ai_output, user_kept) → produces a list of hunks.

Each hunk = {polish_window, kept_window, transcript_window} — captures the three-way relationship between what STT heard, what we wrote, and what the user kept.

Step 3

Classify (deterministic, no LLM)

For each hunk, determine the reason for the user's edit.

  • SttError — original is gibberish + corrected is a proper noun/brand
  • PolishError — user reverted to the transcript form
  • StylePreference — synonym swap (not learnable)
  • StructuralRewrite — large change (not learnable)

Safety gates:

  • is_in_dictionary(original) → if real word and corrected not in vocab → skip
  • is_common_word(corrected) → skip
  • classify_term_type(corrected) → must be brand / acronym / code_identifier
Step 4

Safety Gates (SttError only)

Additional validation for learned corrections before they reach the database.

  • judge_alias_source() — Groq 8B LLM check: is this a real word?
  • appears_in_user_kept() — correction must exist in user's final text
  • script_matches() — Roman script for Hinglish mode
  • is_plausible_alias() — phonetic plausibility check

Routing:

  • 2+ changes in one edit → all go to review card (user picks)
  • 1 change, brand/acronym type → auto-learn immediately
Step 5

Learn (write to DB)

Persist the new knowledge to SQLite and update all caches.

  • vocabulary::upsert — add term to vocabulary
  • stt_replacements::upsert_aliases — add alias (meac→EMIAC)
  • stt_replacements::approve_aliases — mark as approved immediately
  • generate_proactive_distortions — seed 8-12 synthetic STT variants
  • tier2_edit_policy::record_explicit_edit — add edit-policy rule
  • tier2_edit_policy::activate_all_for_term — activate rules
  • Invalidate lexicon cache
  • Trigger ONNX retrain
Step 6

Notify Desktop

Response sent to the Tauri desktop shell with learning outcomes.

  • promoted_terms — newly learned vocabulary
  • review_candidates — ambiguous items for user review
  • ambiguous_terms — multi-candidate aliases
  • negative_terms — corrections that were rejected

Desktop shows toast/picker as needed and refreshes STT bias cache for next recording.

Flow 3: Demotion

When the user reverts a wrong correction
Step 1

Detect Revert

Inside Flow 2 (Steps 2-3): if ai_output contained "EMIAC" but user_kept has "mac" at the same position → the system wrongly corrected mac→EMIAC.

Step 2

Revert Alias

run_alias_revert_pass(): delete the specific alias pair (mac→EMIAC).

Step 3

Demote

stt_replacements::demote() → decrease alias weight. When weight falls to 0 → review_status = 'blocked' (permanent).

Step 4

Edit-Policy Penalty

tier2_edit_policy::mark_removed_feedback() → penalize the edit-policy rule that caused the bad correction.

Step 5

Blocked Forever

Blocked aliases are permanently excluded from all correction paths.

  • Never fires in apply_exact_safe (filtered by review_status)
  • Never fires in tier2 correction (filtered by status)
  • Prevents re-learning (ON CONFLICT keeps 'blocked' status)
  • ONNX retrain excludes blocked pairs from training data
Step 6

Retrain

Trigger ONNX retrain with updated data. Blocked pairs are excluded — the neural scorer will no longer recommend them.

What Changed from v3

Before (v3)

Tier2 Replaces Text

Raw transcript: "meac is down"
↓ Tier2 REPLACES text → "EMIAC is down"
↓ LLM sees corrupted input
↓ Cannot disambiguate: was "meac" really "EMIAC" or "Mac"?
LLM trusts the replacement blindly. Wrong corrections are invisible.
After (v4)

Tier2 Collects Evidence

Raw transcript: "meac is down"
↓ Tier2 COLLECTS EVIDENCE: meac → EMIAC (0.95)
↓ LLM sees raw text + hints
↓ LLM disambiguates using full sentence context
LLM decides. "EMIAC is down" vs "Mac is down" based on surrounding words.
