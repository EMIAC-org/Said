Reliable Learning Pipeline v4

Make AirNote learn a new word in 1–2 corrections — reliably. Brand names in one edit. Ambiguous words in two. No calculated timing tricks. The system should feel like it understood you, not like you had to game it.

Diagnosis — Why Learning Feels Broken

⚠
Problem 1: Blind K=3 Threshold
Every word needs 3 corrections regardless of confidence

The system treats "AirNote" (obvious brand — mixed case, no dictionary match, zero ambiguity) the same as "said" (common English word, Hindi pronoun, ambiguous). Both need 3 separate sightings across 3 separate recordings before anything happens.

classify_term_type() already knows "AirNote" is a brand at first sight. The K-gate ignores this intelligence entirely.

⚠
Problem 2: Passive Distortion Collection
System waits for each Deepgram variant organically

After learning "AirNote", the system only knows the exact STT distortion from that one recording (e.g., "air note"). Next time Deepgram says "airnot" or "airnaught" — unrecognised. The user must correct again, and again, for each new distortion.

The variants() function exists in the Python training script but is never used at runtime to proactively generate aliases.

⚠
Problem 3: 12-Second Idle Gate
Edit watcher waits for 12s of inactivity before acting

After pasting, the edit watcher polls for changes but won't fire the classify call until the user goes completely idle for 12 seconds OR hits the 30-second max. Users edit a word in 2 seconds, then wait for something to happen — nothing does until they stop touching the keyboard for a full 12 seconds.

The "stable edit" pattern (edited once, moved on to writing new text) is indistinguishable from "still actively editing" because the watcher only looks at idle time, not edit semantics.

⚠
Problem 4: No Re-correction Intelligence
Correcting a known word doesn't capture new distortions

When a word is already in vocabulary and the user corrects it again (new Deepgram distortion), the system bumps the weight but doesn't store the new distortion as an alias. The user keeps correcting the same word for different STT mishearings, but only the original alias persists.

⚠
Problem 5: Training Delay
15s debounce + 10–20s training = ~30s before model is live

After an edit triggers learning, the ONNX retrain waits 15 seconds (debounce), then takes 10–20 seconds to train 40 epochs. User won't see the ONNX-based correction for ~30–35 seconds. Meanwhile, STT aliases and edit-policy rules take effect immediately — but without ONNX, novel distortions fall through.

1 Adaptive K-Threshold

Instead of blind K=3 for all words, compute K dynamically based on the word's term type and jargon score at first sight. The system already has classify_term_type() and jargon_score() — they're just not wired into the promotion gate.

K-Threshold Matrix

Term Type Example Detection Signal K Rationale
brand AirNote, iPhone, OpenAI Mixed case, uppercase after pos 0 1 Zero ambiguity. Mixed-case words are never STT accidents.
acronym MACOBS, NASA, EMIAC All-caps, 2–8 chars, alphabetic 1 Users don't accidentally type all-caps. Intent is unambiguous.
code_identifier n8n, k8s, vue-router Contains digits, underscores, or hyphens 1 Digits/symbols in a word → intentional technical term.
proper_noun Vipassana, Anish Initial-cap, rest lowercase, ≥4 chars 2 Could be start-of-sentence capitalisation. One confirmation needed.
phrase auto note, control plane Multi-word input 2 Multi-word → higher chance of coincidental match. Confirm once.
other + high jargon groq (jargon ≥ 0.3) jargon_score() ≥ 0.3, not in common list 2 Looks technical but lowercase — one confirmation.
other + low jargon colour, organise jargon_score() < 0.3 3 Might be user rephrasing. Current threshold appropriate.

Safety Override

🛡
Common-word guard: If is_common_word(original) is true, enforce K = max(computed_K, 2). This prevents the "main" → "Macobs" catastrophe even for brand-type corrections. The original STT form being a common word means the correction might be a false positive.

Implementation

crates/backend/src/store/pending_promotions.rs

pub fn compute_adaptive_k(
    corrected: &str,
    original: &str,
    jargon: f64,
) -> u32 {
    let term_type = vocabulary::classify_term_type(corrected);
    let original_is_common = promotion_gate::is_common_word(original);

    let base_k = match term_type {
        "brand" | "acronym" | "code_identifier" => 1,
        "proper_noun" | "phrase"                        => 2,
        _ if jargon >= 0.3                                 => 2,
        _                                                       => 3,
    };

    // Safety: common-word originals need at least K=2
    if original_is_common { base_k.max(2) } else { base_k }
}

Wiring into record_sighting()

Change the call in classify.rs from record_sighting(..., DEFAULT_K) to record_sighting(..., compute_adaptive_k(corrected, original, jargon)). The pending_promotions table already stores sighting_count — the threshold just becomes dynamic per-word.

2 Proactive Distortion Generation

When a word is promoted to vocabulary, spawn a background task that pre-generates 7–8 likely Deepgram distortions and seeds them as STT aliases. Each distortion is guarded against being a common Hindi/English word.

Distortion Strategies

Strategy A — Orthographic Mutations (from variants())

Port the Python variants() function to Rust. Generates:

  • Single-char deletion: "airnote" → "arnote", "airnot", "ainote"
  • Vowel substitution: "airnote" → "aernote", "airnute", "airnota"
  • Adjacent transposition: "airnote" → "iarnote", "arnote", "airntoe"
  • Terminal rewrites: -c → -h, -s → -z

Strategy B — Phonetic Variants

Use the existing phonetic_key() engine to generate phonetically plausible mishearings:

  • Consonant softening: b↔p, d↔t, g↔k, v↔f, s↔z
  • Aspiration toggle: t↔th, d↔dh, k↔kh, g↔gh
  • Vowel elongation: a↔aa, i↔ee, u↔oo
  • Nasal variants: n↔m at word boundaries

Strategy C — Space/Join Variants (critical for multi-word)

For terms detected as brands or containing capital letters mid-word:

  • CamelCase split: "AirNote" → "air note" (already observed, but ensure stored)
  • Joined lowercase: "AirNote" → "airnote"
  • Partial joins: For 3+ word phrases, generate bigram joins
✨
Key insight: "airnote" (joined) is 100% deterministic for "AirNote" because no common Hindi or English word matches "airnote". This single alias covers Deepgram's most common failure mode (stripping spaces from compound words).

Common-Word Filter

Every generated distortion is checked against is_common_word() before insertion. Additionally, each individual component of a split is checked: 

fn is_safe_distortion(distortion: &str, correct_form: &str) -> bool {
    // Reject if the whole distortion is a common word
    if is_common_word(distortion) { return false; }

    // Reject if distortion is too short (<3 chars)
    if distortion.len() < 3 { return false; }

    // Reject if distortion IS the correct form (no point)
    if distortion.eq_ignore_ascii_case(correct_form) { return false; }

    // Reject if distortion is in system dictionary
    if is_dictionary_word(distortion) { return false; }

    true
}

Weight Strategy

Alias SourceWeightRationale
Observed (user correction) 1.0 Ground truth — this is what Deepgram actually said
Proactive (generated) 0.6 Speculative — might not be a real Deepgram distortion
Re-correction (self-upgrade) 1.0 Another ground truth — new observed distortion

Implementation Sketch

crates/backend/src/store/stt_replacements.rs — new function

pub fn generate_proactive_distortions(
    pool: &Pool,
    user_id: &str,
    correct_form: &str,
    observed_transcript: &str,
    language: &str,
) -> usize {
    let mut distortions: HashSet<String> = HashSet::new();

    // Strategy A: orthographic mutations of lowercase form
    let base = correct_form.to_lowercase();
    distortions.extend(char_deletions(&base));
    distortions.extend(vowel_substitutions(&base));
    distortions.extend(adjacent_swaps(&base));

    // Strategy B: phonetic consonant variants
    distortions.extend(consonant_softening(&base));

    // Strategy C: space/join variants for multi-component
    distortions.extend(camel_case_splits(correct_form));
    distortions.insert(base.replace(" ", ""));  // joined

    // Also include the observed transcript form
    distortions.insert(observed_transcript.to_lowercase());

    // Filter: remove common words and dictionary matches
    let safe: Vec<_> = distortions
        .into_iter()
        .filter(|d| is_safe_distortion(d, correct_form))
        .take(12)  // cap at 12 proactive aliases
        .collect();

    // Insert each as a low-weight alias
    for d in &safe {
        upsert_alias_for_language(pool, user_id, d, d, correct_form, 0.6, language);
    }

    safe.len()
}

3 Faster Edit Detection

Replace the blunt 12-second idle gate with semantic edit detection that fires the classify call as soon as the user's edit stabilises — not when they go completely idle.

Current vs Proposed Timing

Before (v3)
  • 50ms fast poll while editing
  • 200ms slow poll after 2s idle
  • Fire classify after 12s total idle
  • 30s absolute max
  • No distinction between "editing AirNote" and "writing new sentence"
After (v4)
  • 50ms fast poll while editing (unchanged)
  • 200ms slow poll after 1.5s idle (from 2s)
  • Fire classify after 3s of stable text
  • 15s absolute max (from 30s)
  • Smart settle: region-aware stability detection

Stable Edit Detection Algorithm

Detect first meaningful change
Field value differs from post_paste by at least 1 word. Record first_edit_at = now().
Track edit region
Diff post_paste vs current_value to identify which character range was modified. Track the edit region (start_byte..end_byte).
Detect stability
If the edit region hasn't changed for 3 seconds but the user IS still typing (characters appearing outside the edit region), the edit is stable. The user corrected the word and moved on.
Fire classify
Send classify call immediately. Don't wait for full idle. Total latency: ~3–5 seconds from edit, not 12+.

Quick-Fire Heuristic

⚡
Instant classify for single-word replacement: If the diff is exactly one word changed (e.g., "air note" → "AirNote") and the new word passes jargon_score() > 0.3, fire classify after only 1.5 seconds of stability. Single high-jargon word replacements are almost never accidental.

Edge Cases & Safety Guards

Edge Case 1: "Said" — Real Word That's Also a Brand

classify_term_type("Said") returns "proper_noun" (initial cap, rest lowercase, 4 chars). K=2. But "said" (lowercase) is in ENGLISH_COMMON. The adaptive K doesn't apply because the user would correct from "said" (common word) to "Said" (proper noun) — the is_common_word(original) guard forces K = max(2, 2) = 2.

Result: Two corrections needed. First shows a queued toast, second promotes. The proactive distortion generator won't create "said" as an alias because it's a common word.

Edge Case 2: "main" → "Macobs" — The Catastrophe Scenario

classify_term_type("Macobs") = "proper_noun" → K=2. is_common_word("main") = true → K = max(2, 2) = 2.

On first correction: queued (1/2). On second: promoted. Proactive distortions generate "macobs", "mcobs", "macbs", "mecobs" etc. BUT critically: "main" is blocked by is_safe_distortion() because it's a common word.

Safe. The word "main" never becomes an alias for "Macobs".

Edge Case 3: "AirNote" from "air note" — Space-Separated Input

classify_term_type("AirNote") = "brand" → K=1. is_common_word("air note") = false (multi-word, not in list).

Instant promotion. Proactive distortions include "air note" (observed), "airnote" (joined), "airnot" (vowel drop), "arnote" (char deletion). Individual words "air" and "note" are common but the joined forms are not, so they pass the filter.

Result: One correction, 8+ aliases, immediate coverage.

Edge Case 4: "colour" → "color" — Style Preference

classify_term_type("color") = "other". jargon_score("color") = 0.0. K=3.

This IS the intended behaviour. Spelling preferences need multiple confirmations because they could be accidental or context-dependent. The user genuinely needs to correct this 3 times before the system commits.

Edge Case 5: "n8n" — Code Identifier with Digits

classify_term_type("n8n") = "code_identifier" → K=1. is_numeric_junk("n8n") = false (alpha-dominant exception). Instant promotion.

Proactive distortions: "aneten", "naten", "netn" (from seed vocab patterns). None are common words. All safe.

Edge Case 6: Rapid Corrections of Different Words

User corrects "emiac" → "EMIAC" and "macobs" → "Macobs" in the same edit. Both are classified independently. EMIAC gets K=1 (acronym). Macobs gets K=2 (proper_noun) or K=1 if the original was not a common word.

The classify call handles multiple hunks — each is promoted independently. Proactive distortions are generated for each promoted term in parallel.

Guard: Maximum Proactive Aliases

The existing MAX_ALIASES_PER_TERM = 15 cap in stt_replacements prevents alias explosion. Proactive distortions are capped at 12, leaving room for 3 organic aliases from future re-corrections. Combined with the weight=0.6 for proactive (vs 1.0 for observed), the system naturally prioritises real distortions.
