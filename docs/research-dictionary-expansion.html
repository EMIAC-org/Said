Why "agent" became "AirNote"

How AirNote's dictionary gating works, where the gap is, and how to expand the word list so real English words never get falsely corrected.

1 The bug

User said "agent". AirNote typed "AirNote". "agent" is a real English word — it should never be touched by the correction engine.

Root cause — found
There are two separate word-filter functions in the codebase. The ONNX model (Pass 4) uses the full one. But the cluster-fuzzy pass (Pass 3) uses the small one. "agent" exists in the full dictionary but the small filter doesn't know about it.

2 How the dictionary flow works today

Two filter functions, different coverage

Function Word count Source Used by
is_common_word() ~250 Hardcoded list in promotion_gate.rs. Hindi pronouns, verbs, particles + ~50 English words. Pass 2 (edit-policy), Pass 3 (cluster-fuzzy), build_candidates, alias filtering
is_in_dictionary() ~236K /usr/share/dict/words (macOS system dictionary) + hardcoded tech words + is_common_word() Pass 4 (ONNX) only, training data gates

What each correction pass checks before scoring

Pass 1 — Exact Alias Filter: is_common_word() on transcript_form // 250 words "agent" check: MISS — not in 250-word list → alias lookup proceeds Pass 2 — Edit-Policy Rules Filter: is_common_word() on token core // 250 words "agent" check: MISS — not in 250-word list → rule matching proceeds Pass 3 — Cluster-Fuzzy Filter: is_common_word() on token core // 250 words "agent" check: MISS — not in 250-word list → fuzzy scoring proceeds edit_similarity("agent", "airnote") ≈ 0.50 fuzzy score with boosts → 0.80 → ABOVE 0.78 threshold → APPLIED ✗ Pass 4 — ONNX Neural Filter: is_in_dictionary() on token core // 236K words "agent" check: HIT — in /usr/share/dict/words → SKIPPED ✓ // But Pass 3 already replaced it — Pass 4 never gets to see "agent"
The problem in one sentence
Pass 4 (ONNX) has the big dictionary. Passes 1–3 only have the 250-word list. "agent" gets through Pass 3 before Pass 4 can protect it.

3 Immediate fix: unify the filter

Replace promotion_gate::is_common_word() with is_in_dictionary() in Passes 1–3. One-line change per pass. All passes then use the full 236K dictionary.

// tier2.rs — cluster_fuzzy_pass (line ~1199) // BEFORE: || promotion_gate::is_common_word(&core_norm) // AFTER: || is_in_dictionary(&core_norm) // Same change in: apply_edit_policy, build_candidates, apply_exact_safe

4 The bigger problem: /usr/share/dict/words is not enough

Even with the full system dictionary, there are gaps:

WordIn /usr/share/dict/words?Consequence
agentYESFixed by unifying filter
databaseNOCould be "corrected" to a similar vocab term
queueingNOWas corrected to "Kafka" (reported earlier)
terraformNOIf "Terraform" is in vocab, lowercase version gets corrected
webpackNOCould match a brand
kubernetesNOAlready in vocab — fine, but a different user might not have it
prettierNOCould be corrected to something
nginxNOBrand name — already in user vocab typically

The macOS /usr/share/dict/words is a 1963 Unix dictionary. It has 236K words but misses anything invented after ~2000. No "database", no "kubernetes", no "webpack". On Windows, the file doesn't exist at all.

5 How to expand: the options

Option A — Bundle a static word list
Ship a .txt file with the app containing a comprehensive English word list. Load it at startup like we load /usr/share/dict/words.

Best source: dwyl/english-words on GitHub — 479K words, MIT licensed, one JSON file. Includes modern words like "database", "cryptocurrency", "startup". Already used by dozens of spell-checkers and word games.

Size: ~4MB uncompressed, ~1.2MB gzipped. Trivial for a desktop app.

Rust integration: Embed as include_str! at compile time. Zero file I/O. Available on all platforms.

RECOMMENDED — simplest, most reliable, cross-platform.
Option B — aspell/hunspell dictionaries
The spell-checker dictionaries from LibreOffice/Firefox. Available for 90+ languages. English (en_US) has ~120K root words + affix rules that expand to 500K+ forms.

Rust crate: hunspell-rs exists but is a binding to C library. Heavy dependency for just word lookup.

Simpler: Extract the .dic file and ship it as a word list (same as Option A but from a different source).

GOOD — more linguistically complete, but the C binding is heavyweight.
Option C — NLTK / WordNet corpus
Python's NLTK ships a words corpus with ~236K words (similar to Unix dict) and WordNet with ~155K words + definitions. Can export as a flat text file.

Limitation: Still misses modern tech terms. Same era as /usr/share/dict/words.

OK — not much better than what we have.
Option D — HuggingFace tokenizer vocabulary
Large language model tokenizers (BERT, GPT-2, Llama) have vocabularies of 30K-128K tokens. These include common words, subwords, and modern terms.

Problem: Subword tokenization. "database" might be split as "data" + "base". Can't directly use as a "is this a word" lookup.

Workaround: Filter to tokens that are full words (no ## prefix, no Ġ prefix). GPT-2 yields ~28K usable full words. Includes "database", "kubernetes", "tensorflow".

INTERESTING — modern vocabulary, but requires filtering.
Option E — Wiktionary dump
Wiktionary has ~1M English entries. Available as XML or JSON dumps. Includes every word any contributor has ever documented, including modern tech terms, brand names, and slang.

Size: ~80MB uncompressed for just headwords. Too large to embed.

Better: Pre-filter to words with frequency > 1 in a corpus (e.g., Google Books Ngrams). Gives ~350K high-confidence words.

POWERFUL — most comprehensive, but needs preprocessing.
Option F — Google 10K + tech supplement
Google's 10K most common English words + a hand-curated list of ~2K tech/brand terms (docker, kubernetes, webpack, nginx, redis, postgres, etc.).

Size: ~120KB. Tiny.

Limitation: Only covers common words. Misses obscure but real words like "ameliorate" or "penurious" — these would still get scored by the ONNX model.

LIGHTWEIGHT — smallest footprint, but gaps remain.

6 Recommendation

Option A + tech supplement = best tradeoff

Bundle dwyl/english-words (479K words, MIT licensed) as a compile-time include_str! resource. Add a hand-curated tech-terms supplement (~500 terms: docker, kubernetes, webpack, nginx, redis, postgres, graphql, terraform, vercel, supabase, etc.).

Why:

  • Cross-platform — works on macOS, Windows, Linux (no /usr/share/dict dependency)
  • Modern vocabulary — includes "database", "startup", "cryptocurrency", "algorithm"
  • Small — ~1.2MB compressed, embedded at compile time, zero file I/O
  • MIT licensed — no legal risk
  • Easy to update — just re-download the JSON and rebuild

For Hindi: keep the existing HINDI_COMMON list (250+ words). Expand to ~500 via Hindi Wiktionary frequency list. No good Rust crate exists for Hindi spell-check — the curated list is the right approach for now.

Implementation sketch (Rust)

// crates/backend/src/tier2.rs — replace DICTIONARY lazy static // Embed the word list at compile time (zero file I/O) static BUNDLED_WORDS: &str = include_str!("../data/english-words.txt"); static DICTIONARY: Lazy<HashSet<String>> = Lazy::new(|| { let mut words: HashSet<String> = BUNDLED_WORDS .lines() .map(|l| l.trim().to_ascii_lowercase()) .filter(|w| w.len() >= 3 && w.len() <= 20) .collect(); // Tech supplement — modern terms the 479K list may still miss for w in &[ "docker", "kubernetes", "webpack", "nginx", "redis", "postgres", "graphql", "terraform", "vercel", "supabase", "kibana", "elasticsearch", "mongodb", "firebase", "heroku", "kubernetes", "queueing", "npm", "webpack", "prettier", // ... ~500 tech terms ] { words.insert(w.to_string()); } // Hindi common words from promotion_gate::HINDI_COMMON // (already covered by is_in_dictionary calling is_common_word) words }); // Then: upgrade ALL passes to use is_in_dictionary() instead of is_common_word()

7 Platform coverage comparison

Platform Current (v2.2.0) After fix (v2.2.1+)
macOS (Apple Silicon) 236K words from /usr/share/dict/words + 250 Hindi. Only Pass 4 uses full dict. 479K bundled + tech supplement + Hindi. All 4 passes use it.
macOS (Intel) Same as above Same — bundled, no platform dependency
Windows 0 words — /usr/share/dict/words doesn't exist 479K bundled — identical coverage to macOS
Linux Varies by distro (~100K-236K) 479K bundled — consistent everywhere
Key insight
Windows has been shipping with zero dictionary words this whole time. On Windows, every single token reaches the ONNX model and cluster-fuzzy unchecked. The bundled dictionary fixes this for all platforms simultaneously.
