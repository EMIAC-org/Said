01 / The one-line answer

What kind of ML is this?

It is supervised binary classification used like a ranker. For every suspicious token, Said asks: "Is this token a garbled version of this protected word?"

The clean explanation: "We train a tiny local scorer on user correction pairs. It scores possible replacements, but strict safety gates decide whether anything is actually changed."
Input

A pair

("macops", "Macobs")

The model never sees the whole sentence first. It scores one raw token against one candidate term.

Output

A probability-like score

0.94 means likely match. 0.12 means leave it alone.

Decision

Threshold + margin

Even if the scorer likes something, Said applies only when the best match is clearly better than the second best.

02 / Runtime pipeline

Where the learning sits in Said

The scorer does not replace Local speech and it does not replace the LLM. It sits between them. Local speech gives raw text. Local learning repairs protected words. The LLM then polishes cleaner text.

Step 1
Mic audio
Caps Lock recording produces WAV/PCM audio.
Step 2
Local speech STT
Outputs honest raw transcript, often garbling custom terms.
Step 3
Exact aliases
meac is already known, so it becomes EMIAC.
Step 4
Edit policy
Confirmed user variants fire before fuzzy guesses.
Step 5
ML scorer
Scores remaining suspicious tokens against protected vocab.
Step 6
Safety gates
Common words, low margin, weak score, and risky terms are vetoed.
Step 7
LLM polish
Receives cleaner text and focuses on tone/format, not guessing names.
Important:

We keep trust order conservative: exact alias first, confirmed edit-policy second, ML scorer third, safety gates final. The model suggests; gates decide.

The scorer is a small weighted calculator

The easiest high-ROI model is logistic regression or a tiny tree model over hand-built features. It can later be exported as ONNX, but ONNX is just the portable file format. ONNX does not automatically mean neural network.

04 / Training data

Training means showing good pairs and dangerous bad pairs

The hardest part is not teaching the model that macops -> Macobs is good. The hard part is teaching it that corps -> Macobs is dangerous because corps may be a real intended word.

Training row Raw token Candidate Label Meaning
Positive meac EMIAC 1 User explicitly corrected this.
Positive macops Macobs 1 Looks and sounds like the protected term.
Hard negative main EMIAC 0 Common Hinglish word. Never rewrite it.
Hard negative dock Docker 0 Real English word that looks tempting.
Wrong candidate macops EMIAC 0 Token may need fixing, but not to this term.

Where positives come from

  • User edits pasted output.
  • Classifier says the edit was an STT correction.
  • Deterministic diff extracts the exact changed span.
  • Protected terms like EMIAC, Macobs, n8n become learning targets.

Where negatives come from

  • Common English/Hindi/Hinglish words.
  • Real dictionary words close to dev terms.
  • Wrong candidates for the same raw token.
  • Past corrections the user removed or rejected.
05 / Safety and quality

Quality comes from saying "no" often

The scorer can be powerful, but Said should be conservative. A missed correction is annoying. A wrong correction changes meaning and destroys trust.

Apply
macops -> Macobs
Score is high, candidate is protected, token is not a common word, and second-best candidate is far behind.
Reject
dock -> Docker
Score may look tempting, but dock is a real word. The dictionary/common-word veto blocks it.

Threshold

Do not apply unless score is high enough, for example >= 0.86.

Margin

Best candidate must beat second-best clearly. Otherwise the model is confused.

Protected terms

Only fix brands, acronyms, proper nouns, identifiers, and starred local vocabulary.

Veto list

Common words like main, time, can, go stay untouched.

06 / ONNX, neurons, and RL

These are different things

This is where confusion usually happens. ONNX, neural network, and RL are not the same concept.

ONNX file format

ONNX is a portable model artifact. Rust can load it with ONNX Runtime. The model inside can be logistic regression, a tree model, or a neural net.

In simple words: ONNX is the container, not the intelligence itself.

Neural net optional

A neural model uses hidden neurons. It can learn more complex patterns, but needs more data and is harder to debug.

For Said v1: start with a simpler scorer unless eval proves it is not enough.

RL not the right label

User edits are feedback, but we are not running classic reinforcement learning. We are converting edits into labeled examples.

Correct term: supervised learning from correction feedback.

07 / End-to-end learning loop

How it improves after a user edit

The immediate learning should come from SQLite edit-policy memory. The model refresh can happen later after enough clean examples.

1

User says a sentence

Example: "macops ka data bhejo". Local speech may output macops or mecobs.

2

Said produces output

If no safe rule exists yet, it may leave the token unchanged. This is intentional until we have evidence.

3

User edits to the correct word

User changes macops to Macobs. The deterministic diff must extract this exact pair.

4

SQLite policy updates immediately

Local memory stores macops -> Macobs as a candidate. After enough confirmations, it becomes active.

5

Future dictation uses it before polish

Next time, Said repairs the token locally before the LLM sees it.

6

Model refresh happens later

After enough clean examples, the offline trainer refreshes the scorer and exports an updated ONNX artifact.

08 / How to explain this to anyone

Your crisp explanation

Use this language when someone asks what you built. It is technically accurate without sounding overcomplicated.

Bad explanation
"We trained RL/neural STT."
->
Good explanation
"We trained a local correction scorer."

30-second version

"Said does not fine-tune the speech model. It keeps user data local and learns from edits. Each edit creates supervised examples like meac -> EMIAC. A tiny scorer ranks possible fixes, and strict gates apply only high-confidence protected-word corrections before LLM polish."

Technical version

"It is a local supervised binary classifier used as a ranker. Features include edit distance, phonetic similarity, dictionary-word detection, term type, and user reward counts. We train with positives and hard negatives, export the model to ONNX, and run inference in Rust."

The product principle:

Do not make the model powerful first. Make the data clean, the labels reliable, and the false-positive tests brutal. Then even a tiny model becomes useful.
