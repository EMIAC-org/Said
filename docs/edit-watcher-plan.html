Problems Found 13 total

🔴 P1: Mutex Poisoning = Silent Death

If EditWatcherState mutex is poisoned (watcher panicked), ALL future edit-watches are silently disabled. No error to user, no recovery until app restart.

main.rs:3848 — Err(_) => return silently

🔴 P2: AX-Blind Apps Can't Learn

Lark, Claude, Notion, some Electron apps — AX API returns empty. Edit-watch is completely skipped. Earlier clipboard fallback was removed for being "too autonomous".

main.rs:4122 — ax_unreadable_skip, no fallback

🔴 P3: 5s Idle = Watcher Dies

If user pauses typing for 5 seconds (thinking, reading), watcher declares "done" and fires the classify call. User's remaining edits are LOST. Very common with slow typists or multi-edit sessions.

Idle timeout: 5s — too aggressive for careful corrections

🟠 P4: Multiple Edits = One Event

User corrects 3 words in one sentence. All changes arrive as a single classify-edit call. The deterministic classifier handles each hunk independently, but extract_kept sends the ENTIRE edited text — context for per-token attribution is weak.

"automot hi dikh" → "AutoNote ye likh" = 1 event, 3 corrections

🟠 P5: Polling Too Slow (150ms)

Fast typists can enter 3-4 keystrokes between polls. The watcher may see "automot" → "AutoNote" as a single jump, missing intermediate states. For reactive feel, sub-100ms polling is needed.

150ms fast / 500ms slow — should be 50ms / 200ms

🟠 P6: 700ms Initial Delay

The watcher waits 700ms after paste before first AX read. A fast corrector could have already edited and moved on. Should pre-read immediately after paste and retry if empty.

700ms delay = user already typing by the time we start watching

🟠 P7: Same-App Field Switch

User clicks a different text field in the SAME app (same PID). Watcher continues monitoring the new field, thinking user is editing Said's output. No detection mechanism for within-app focus changes.

Slack: click from message input → thread input = wrong field

🟡 P8: AX Timeout Drops Edits

Each AX read has a 500ms timeout. Slow Electron apps (Slack, VS Code) can timeout, returning None. Treated as "no change" — real edits are silently missed.

AX timeout 500ms → None → "field unchanged" (wrong)

🟡 P9: Undo (Cmd+Z) Confusion

If user undoes an edit during the watch window, watcher captures the intermediate state. Partial undos create garbled learning data.

Type "AutoNote" → Cmd+Z → back to "auto note" → learns nothing (good) or learns wrong (bad)

🟡 P10: App Closed During Watch

If the target app quits or crashes during the 30s watch window, AX reads return None. best_candidate saves the last valid read, but the watcher keeps polling a dead process.

User quits Chrome → watcher polls dead PID for 5s before idle timeout

🟡 P11: Short Text Garbage Gate

shares_word_overlap filters words ≤2 chars. If polished text is "I am ok" (all short words), ANY candidate passes the garbage gate. False positives with short utterances.

Polished: "I am ok" → ref_words = [] → any non-empty text accepted

🟡 P12: CancellationToken Race

Cancelling a watcher doesn't wait for it to stop. New watcher + old watcher can overlap briefly (up to 150ms). Both read AX and potentially both send classify-edit.

Rapid record → cancel → record → two watchers alive for ~150ms

🟡 P13: No AX Latency Adaptation

If AX reads consistently take 200-400ms (heavy Electron), the 150ms poll interval means the watcher is always behind. Should detect slow AX and adjust cadence.

AX takes 300ms → 150ms poll → every read overlaps, queue builds up

Fix Plan — 4 Phases

1
Speed & Responsiveness
Fixes P5, P6, P3 • ~2 hours

Make the edit watcher feel instant. Users should see corrections captured within 50ms of their last keystroke, and the watcher should wait long enough for thoughtful multi-edit corrections.

  • Reduce FAST_INTERVAL from 150ms → 50ms main.rs:3790 AX reads take 5-15ms. At 50ms polling, we catch every keystroke with room to spare. CPU impact is negligible (one AX syscall per 50ms).
  • Reduce SLOW_INTERVAL from 500ms → 200ms main.rs:3791 When user pauses 2s then resumes typing, catch the first keystroke within 200ms instead of 500ms.
  • Reduce initial delay from 700ms → 400ms main.rs:3899 700ms was overly conservative. Paste animation is ~200ms, AX cache rebuild is covered by the 3-retry loop. 400ms is safe for all tested apps.
  • Increase IDLE_TIMEOUT from 5s → 8s main.rs:3786 Users who pause to think (5-7s) currently lose their remaining edits. 8s covers the "read, think, correct" cycle while still being responsive. Revisit with telemetry.

2
Crash-Proof Reliability
Fixes P1, P10, P12 • ~1.5 hours

The watcher must never silently die. Every failure mode should either recover automatically or alert the user.

  • Recover from mutex poisoning — replace poisoned mutex with fresh one main.rs:3848 Instead of Err(_) => return, create a new Mutex and replace the poisoned one. Log a warning. The watcher continues working.
  • Detect dead target PID and exit early main.rs poll loop Check kill(pid, 0) once per slow-interval poll. If the process is dead, immediately finalize with best_candidate and send classify-edit. Don't waste 5s waiting.
  • Await old watcher cancellation before starting new one main.rs:3830 After prev.cancel(), add a brief tokio::task::yield_now() or a 10ms sleep to let the old watcher exit its current poll iteration. Prevents overlapping watchers.
3
Multi-Edit & Focus Intelligence
Fixes P4, P7, P9 • ~3 hours

Handle the hard cases: multiple corrections in one sentence, field switches within the same app, and undo detection.

  • Track AX element identity (not just PID) for within-app field detection paster/src/lib.rs Store the AXUIElement pointer/role of the focused field at paste time. On each poll, compare the current focused element's identity. If it changed (different field in same app), stop watching.
  • Detect Cmd+Z by tracking if field value reverts toward post_paste main.rs poll loop If now_val becomes closer to post_paste than to last_val (edit distance decreasing), the user is undoing. Mark this in capture_meta so the classifier can weight it lower.
  • Multi-edit hunk splitting already done — verify with real data classify.rs: classify_single_token_change() Already implemented: equal-count multi-token hunks are split per-token. "automot hi" → "AutoNote ye" produces 2 independent classifications. Verify with logs from real usage.
  • Capture field snapshots at each change — not just final state main.rs poll loop Store a Vec of (timestamp, field_value) for every change detected. Send the edit history to the backend so the classifier can see the full correction timeline, not just start→end.
4
AX-Blind Recovery & Adaptive Cadence
Fixes P2, P8, P11, P13 • ~3 hours

Handle apps where AX doesn't work at all, adapt to slow AX environments, and fix edge cases in the garbage gate.

  • AX-blind passive learning: compare clipboard at watcher end main.rs:4122 When AX is blind, DON'T actively capture (no Cmd+A/C). Instead, check if the clipboard content changed during the watch window and if it overlaps with polished text. If the user copied their edited text to clipboard (common in Slack/Discord before paste elsewhere), learn from it passively.
  • Adaptive polling: measure AX latency and scale interval main.rs poll loop Time each blocking_ax_option call. If AX reads consistently take >100ms, increase poll interval to 2× the measured latency. Prevents queue buildup in slow Electron apps while staying fast in native apps.
  • Fix short-text garbage gate — use char-level overlap for ≤5 word texts main.rs:4339 When polished text has ≤5 words, switch from word-overlap to character-overlap (>50% of chars shared). Prevents "I am ok" from accepting any candidate.
  • AX timeout retry with exponential backoff main.rs:3799 When AX read times out (500ms), retry once with 1s timeout before declaring None. If 2+ consecutive timeouts, switch to SLOW_INTERVAL to reduce AX pressure.
