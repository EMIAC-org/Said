Edit Review card — window size formula

Window sizing for the review card

The native status bar window must resize to fit the review card content. Formula:

Width: 300px (fixed)
Height: header (38) + changes (N × 38) + gaps (N × 5) + footer (36) + padding (28) = 102 + N × 43

1 change: 300 × 145
2 changes: 300 × 188
3 changes: 300 × 231
4 changes (max): 300 × 274

Cap at 4 rows. If more than 4 changes detected, show top 4 by confidence and group the rest under "and N more..."

Decision logic — when to show what

Case 1: Single word, high confidence (K=1)

  • Term type is brand, acronym, or code_identifier
  • Original is NOT a common word
  • Action: Auto-learn instantly, show green "Learned" pill
  • No review card — this is unambiguous

Case 2: Single word, moderate confidence (K=2)

  • Term type is proper_noun or phrase
  • Action: Record sighting, show yellow "1 more edit" pill
  • No review card — just a status update

Case 3: Multiple changes detected (2+)

  • Show the Edit Review card
  • Each change is a selectable row
  • User picks which ones to learn
  • Selected: learn + distortion seed + retrain
  • Unselected: completely ignored, not even queued

Case 4: Single word, low confidence (K=3)

  • Term type is other, low jargon score
  • Action: Show review card with 1 row so user can explicitly confirm
  • This replaces the old blind K=3 queue — user decides on the spot

Edge: User added a word not in transcript

When the classifier detects a StructuralRewrite (user inserted content that wasn't in the STT output at all), that change is not learnable because there's no source distortion to map from.

In the review card, these rows appear greyed out with "(not in audio)" label and are unselectable. They're shown for transparency ("we saw you added this") but can't be learned because there's nothing to teach the STT about.

Example: User says "deploy to Kubernetes using Docker" but STT only heard "deploy to cubernetti using" — the user adds "Docker" manually. There's no STT distortion of "Docker" to learn from.

What happens after "Learn N"

  1. Selected changes are sent to POST /v1/confirm-batch
  2. Each is promoted to vocabulary (adaptive K, bypasses queue)
  3. Proactive distortions generated for each
  4. Edit-policy rules activated
  5. Lexicon cache invalidated
  6. ONNX micro-retrain triggered
  7. Card collapses to green pill: "Learned N corrections"
  8. 3s later → idle

Window interactivity toggle

The status bar is click-through by default. When the review card appears:

  1. Call set_status_bar_interactive(true) — enables mouse events on native window
  2. User interacts with checkboxes and buttons
  3. On "Learn N" or "Skip all" or auto-dismiss (15s timeout):
  4. Call set_status_bar_interactive(false) — back to click-through
