AirNote / provider & BYOK decision

Make polish provider choice a user choice — without adding another messy pipeline.

Cerebras Gemma 4 is currently the server-polish default. BYOK is feasible with a small extension of the runtime we already have, but it must be a controlled provider contract, not arbitrary endpoints or silent fallback billing.

RecommendationShip a curated OpenAI-compatible BYOK tier first: Groq, DeepInfra, DeepSeek, Gemini. Keep Cerebras as AirNote-managed default. Add OpenRouter later as an explicit advanced gateway, never as a hidden fallback.

Implementation agenda

Smallest safe route to real BYOK

Unify transport

Replace copy-pasted provider stream modules with a narrow OpenAI-compatible adapter. Preserve the current prompt, streaming behavior, timeout, and post-token romanization.

Add four presets

Groq, DeepInfra, DeepSeek, Gemini. A preset supplies only reviewed endpoint/model choices and request quirks — not a free-form URL.

Make cost behavior honest

Show active provider/model in the UI. Validate a key with a bounded request. Never fall back to AirNote credits unless the user enables it.

Benchmark before promotion

Run the existing lab’s fixed history suite against every candidate with the same prompt. Score exact preservation, Hindi/Hinglish romanization, hallucination, latency, and output length.

Key-custody truth: the existing control-plane pattern encrypts keys at rest, but AirNote’s server still holds and uses them. That is acceptable for a normal hosted BYOK feature if disclosed; it is not “key never leaves the device.” A later privacy tier can use a desktop-held key or a user-run local gateway.
Why price alone is not the answer

Polish is a constrained multilingual transformation, not generic chat. The cheapest model can cost more in user trust if it changes identifiers, expands a short sentence, mishandles Hinglish, or leaks thinking text. The lab should use the same frozen prompt and held-out history for every model. Promote a provider only when it clears the current Gemma baseline on correctness and p95 latency at the desired price.

What to measure in the lab
  • Exact output / minimum-edit score against your approved historical final text.
  • Technical term and identifier preservation.
  • Hindi/Devanagari → Roman Hinglish accuracy and no mojibake.
  • Hallucination / added-content rate.
  • p50 and p95 time-to-first-token plus completion time.
  • Input and output token counts to calculate actual cost per utterance.
Why OpenRouter is not the V1 default

It is useful for power users because one account can hold upstream provider keys and define an order. Its documented routing can proceed from prioritized keys to OpenRouter endpoints to fallback keys unless configured otherwise. For a user who selected BYOK to control cost and data path, that extra routing layer should be an explicit advanced choice, not invisible behavior.

High confidence: local architecture and API compatibility. Medium confidence: model quality for Hinglish polish until benchmarked.
