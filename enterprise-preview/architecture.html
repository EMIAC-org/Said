Meeting Data Flow

Capture

Each device captures its owner's voice. Audio stays local — only polished transcript text is sent to the meeting server. No raw audio ever leaves the device.

Process

The server interleaves transcripts by timestamp, tags each chunk with the speaker's identity, and feeds the running transcript to the AI pipeline every 30 seconds.

Sync

When the meeting ends, one click creates Lark Tasks (per assignee), a Lark Doc (summary + decisions), and attaches the full transcript. All via Lark Open API.

Privacy & Security

What stays on the device

  • ✓ Raw audio — never sent to the server
  • ✓ API keys (Local speech, Groq)
  • ✓ Personal dictation history
  • ✓ Learning pipeline corrections

What goes to the server

  • → Polished transcript text (per-meeting only)
  • → Speaker identity (from Lark OAuth)
  • → Timestamps for interleaving
  • → AI-generated summaries and tasks

Self-hosted guarantee: In Enterprise mode, the meeting server runs on the customer's own VPS. No data touches Said's infrastructure. The Docker image contains everything — no external dependencies besides the customer's own Lark app credentials and LLM API key.
